# Handover GraphRAG — a departed colleague's mailbox as a knowledge graph

> **Relate by Neo4j Hackathon entry.** A 10-year import operator leaves a freight forwarder. Her successor inherits
> 292 e-mails and five SOP PDFs. This project turns that pile into a Relate knowledge graph and lets the successor ask
> *who decided what, why, under which rule, and what is still open* — with every answer cited back to a mail or a clause.

Everything here is synthetic (fictional company **Meridian Freight Co.**, Busan). The ground truth is generated by code
(`world/world.yaml`), so every answer can be checked against a known fact — the LLM only wrote the prose of the mails
and SOPs.

## What a judge can run in 5 minutes

The Relate store `data/handover.rl` (≈8 MB) and the whole corpus are committed. No API key is needed to explore the graph:

```bash
git clone https://github.com/gracelee087/handover-graphrag.git && cd handover-graphrag
uv sync                                   # Python 3.13; installs relate-db, sentence-transformers, docling ...
uv run python src/store.py                # prints indexes + node counts of data/handover.rl
relate serve --bolt 7687 --database ./data/handover.rl --read-only   # optional: open it in any Cypher client
```

Asking questions needs an Anthropic key (`cp .env.example .env`, fill `ANTHROPIC_API_KEY`):

```bash
uv run python src/retrievers.py "Who decided how the demurrage on HBL MFCIM260009 would be split?" --mode all
uv run python src/agent.py --demo         # the handover agent (Claude tool-use over the graph), 4 scripted questions
uv run python src/agent.py                # interactive
uv run python eval/run_eval.py            # 40 gold questions x 3 retrievers, LLM-judged
```

Rebuilding the store from the committed corpus (Docling PDF parsing + Claude extraction, ≈ USD 2.3 at list price;
LLM caches under `data/mail/extract` and `data/sop/json` make a re-run free):

```bash
uv run python build_all.py --fresh
```

Regenerating the corpus itself (`src/gen_world.py` → `src/gen_mail.py` → `src/gen_sop.py`) is deterministic given the
cached LLM output; without the cache it costs ≈ USD 2.8.

## The graph

```
(Person)-[:WORKS_AT]->(Organization)
(Shipment)-[:CARRIED_BY|CLEARED_BY|CONSIGNEE|SHIPPER]->(Organization)
(Person)-[:SENT]->(Email)-[:TO|CC]->(Person)      (Email)-[:IN_THREAD]->(Thread)
(Email)-[:REPLIES_TO]->(Email)                    (Email)-[:ABOUT]->(Shipment)      (Email)-[:HAS_ATTACHMENT]->(Attachment)
(Chunk)-[:FROM_DOCUMENT]->(Email)                 one Chunk per mail, 384-d embedding + full-text index
(Issue|Decision|Task)-[:CONCERNS]->(Shipment)     extracted by Claude per thread
(Decision)-[:DECIDED_BY]->(Person)  (Task)-[:ASSIGNED_TO]->(Person)  (Issue)-[:RAISED_BY]->(Person)
(Decision)-[:RESOLVES]->(Issue)     (Task)-[:HAS_DEADLINE]->(Deadline)
(Issue|Decision|Task)-[:FROM_CHUNK]->(Chunk)      provenance: which mail says so
(SOPDocument)-[:HAS_SECTION]->(Section)-[:HAS_CLAUSE]->(Clause)   Docling-parsed PDFs, NEXT_SECTION/NEXT_CLAUSE, embeddings
(Email)-[:CITES]->(Clause)          (Issue|Decision)-[:GOVERNED_BY]->(Clause)
```

## How Relate is used

* **Embedded store, one file.** `relate.connect("data/handover.rl")` — every script (loader, retrievers, agent, eval)
  opens the same file; no server, no credentials. Judges get the exact graph that produced the numbers below.
* **Cypher DDL/DML**: unique constraints, `UNWIND $rows MERGE` bulk loads, `vector(list, 384, FLOAT32)` properties.
* **Vector search**: `CREATE VECTOR INDEX … OPTIONS {indexConfig: {vector.dimensions: 384, vector.similarity_function: 'cosine'}}`
  and `SEARCH c IN (VECTOR INDEX chunk_embedding FOR vector($v, 384, FLOAT32) LIMIT $k) SCORE AS score`.
* **Full-text search**: `CREATE FULLTEXT INDEX chunk_text … ON EACH [c.text]` and `SEARCH c IN (FULLTEXT INDEX chunk_text FOR $q LIMIT $k)`.
* **Hybrid retrieval** (graph mode): vector ∪ full-text hits fused with reciprocal-rank fusion, plus identifier anchoring —
  an HBL/MBL/container number in the question pulls the Shipment card and everything extracted about it. Pure vector
  search cannot match identifiers like `MFCIM260009`; the full-text index can.
* **Graph expansion**: each seed mail is expanded to sender/org/recipients, shipment card, extracted Issue→Decision→Task
  chain with the people on them, governing SOP clauses, thread neighbours. The SOP clauses are searched directly as well
  (vector + full-text over `Clause`), so rule questions get the clause text even when no mail cites it.
* **Deterministic entity resolution in Cypher/Python**: a task restated in the handover mail is linked to its original
  (`DUPLICATE_OF`, same owner + due date + compatible shipment + word overlap), so "what is open" is not double-counted.
* **Text2Cypher** against a hand-written schema string (Relate has no APOC, so `apoc.meta.data` is unavailable).
* Optional: `relate serve --bolt` exposes the same file to Bolt clients; `relate push` mirrors it to Neo4j Aura.

## Three retrievers, one agent

| mode | seed | context handed to Claude |
|---|---|---|
| `vector` | top-6 chunks by cosine | the mail texts only (baseline) |
| `graph` | hybrid seeds + identifier anchors | mails **plus** the expanded subgraph (people, shipment, decisions, tasks, clauses) |
| `text2cypher` | Claude writes one Cypher query | query rows (best for counts and lists) |

`src/agent.py` wraps the graph in six tools (`search_mailbox`, `shipment_file`, `open_tasks`, `sop_clause`, `read_mail`,
`run_cypher`) and lets Claude (Tool Runner, `claude-opus-5-5`) choose — a lookup question goes to search, a count goes
to Cypher, a compliance question fetches the clause and says whether the mails complied.

## Evaluation

40 questions with gold answers (`eval/questions.json`: 8 each of factual / aggregate / multi-hop / compliance / handover),
answered by each retriever and graded by Claude against the gold (correct / partial / wrong) plus a keyword check.

Final run (2026-11-19), verdicts per type as correct / partial / mean score (correct = 1, partial = 0.5):

| question type | n | vector | graph (hybrid + expansion) | text2cypher |
|---|---|---|---|---|
| factual | 8 | 4 / 0 / 0.50 | 8 / 0 / **1.00** | 8 / 0 / **1.00** |
| aggregate | 8 | 1 / 2 / 0.25 | 1 / 2 / 0.25 | 7 / 0 / **0.88** |
| multihop | 8 | 6 / 1 / 0.81 | 7 / 1 / **0.94** | 7 / 1 / **0.94** |
| compliance | 8 | 1 / 5 / 0.44 | 5 / 3 / **0.81** | 2 / 4 / 0.50 |
| handover | 8 | 3 / 2 / 0.50 | 4 / 4 / 0.75 | 5 / 3 / **0.81** |
| **all** | 40 | 15 / 10 / 0.50 | 25 / 10 / 0.75 | 29 / 8 / 0.82 |

Mean latency per answer: vector 4.6 s, graph 5.4 s, text2cypher 10.5 s (two LLM calls). Answering the 120 questions
cost USD 3.75, judging USD 0.72.

What the numbers say:

* **Graph expansion is what makes mail retrieval useful.** Same seeds, same model: adding the subgraph (people, shipment,
  extracted decisions, governing clauses) lifts factual questions from 4/8 to 8/8 and compliance from 0.44 to 0.81.
* **Counting needs Cypher.** Top-k retrieval cannot answer "how many mails about Blue Harbor Foods" (133). Text2Cypher
  gets 7/8 aggregates; both text retrievers fail them. The agent routes such questions to `run_cypher`.
* **Compliance needs the clause text next to the case.** Text2Cypher often finds the clause but not the case, or vice
  versa; graph mode gets both because `GOVERNED_BY` and direct clause search put them in one context.
* **Remaining misses** are mostly "the extractor also found a real, undated task the gold list did not have" (Q16, Q39)
  and two breaches the mails never state as breaches (Q30: the SOP violation has to be inferred from a same-day booking).

Three runs were needed to get here; the earlier two are kept in the git history of `HANDOFF.md`. The biggest gain came
not from retrieval but from the corpus: the first corpus version carried no due dates in the mails, so no retriever could
answer the handover questions (2/8 everywhere). Ground truth and corpus have to be checked against each other.
